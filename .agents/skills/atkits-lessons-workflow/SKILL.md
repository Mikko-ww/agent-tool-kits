# atkits 经验提取工作流

本技能只服务于 `agent-tool-kits` 这个仓库。它不是通用技能，不进入 Release，不分发到其他机器，也不需要在 `profiles/global.yaml` 里登记。

当用户要求“复盘”“总结经验”“把这个坑记下来”“更新 AGENTS-LESSONS”时，使用本技能。引入新技能入库走 `atkits-intake-workflow`，发布走 `atkits-release-workflow`。

设计参考：aihero `/retro`（会话复盘 + 分类路由 + 只提议不写入）与 incident-postmortem（无责复盘 + 五问法）。

## 核心原则

- **不是所有问题都是经验**。一次性偶发、纯猜测、无法转成行动的抱怨，都不进 `AGENTS-LESSONS.md`。
- **对系统不对人**。描述“什么条件导致了问题”，不追究是谁做的。
- **只提议，不写入**。候选经验经用户挑选确认后，才修改文件。
- **宁缺毋滥**。`AGENTS-LESSONS.md` 的价值在密度，不在长度；每新增一条都要能改变 agent 的下一步行为。

## 提取流程

### 1. 收集事实

从会话记录、命令输出、报错和退出码中收集证据，不臆测、不脑补。没有证据的问题最多作为“待观察”，不进入候选。

### 2. 复述问题（五问法压缩版）

对每个候选问题，用三句话说清：

1. **现象**：实际发生了什么（含证据出处）。
2. **根因**：什么条件让它发生（环境特性、规则缺失、工具行为，不归因于人）。
3. **影响**：下次在什么条件下还会复发。

说不清根因的，先标记“根因未明”，不提炼。

### 3. 准入判定（六条标准，逐条过）

| # | 标准 | 不满足时的处理 |
|---|---|---|
| 1 | **会复发**：由环境特性或规则缺失导致，条件重现就会再发生 | 一次性偶发 → 丢弃 |
| 2 | **根因明确**：能说清为什么发生 | 根因未明 → 待观察 |
| 3 | **可转行动**：能写成一条改变行为的“正确做法” | 无法行动 → 丢弃 |
| 4 | **有证据**：命令输出、报错、退出码等可引用 | 纯猜测 → 丢弃 |
| 5 | **够稳定**：不会因临时状态很快失效 | 即将过时 → 标注适用范围或暂缓 |
| 6 | **不重复**：AGENTS.md、AGENTS-LESSONS.md、现有技能中没有等价条目 | 已有 → 合并强化，不新增 |

六条全过才成为候选经验。

### 4. 分类路由

经验不止一个去处，先分类，类别决定落地位置：

| 问题类型 | 落地方式 |
|---|---|
| 机械性违规（能被工具检查：版本一致性、打包约束、frontmatter 格式） | 建议自动化检查：测试、脚本校验、CI；**不写散文** |
| 导航问题（找文件/事实花了过多轮次） | 补充 AGENTS.md 代码地图或导航指针 |
| 判断类问题（工具无法约束的取舍） | `AGENTS-LESSONS.md` 一条“问题 / 正确做法” |
| 环境类问题（沙箱权限、工具回退路径） | `AGENTS-LESSONS.md` 环境与工具分组 |
| steering 文件膨胀或失效条目 | 提议精简 AGENTS.md / 删除 no-op 规则 |

能自动化的优先自动化：一条会失败的检查，胜过一段没人执行的说明文字。

### 5. 提炼条目

`AGENTS-LESSONS.md` 统一条目格式：

```markdown
- **问题**：<现象 + 根因，一句话>
  **正确做法**：<可执行的替代动作>
```

要求：一句话说清问题；正确做法写成命令或明确动作；必要时附适用条件。不写长篇分析、不写过程记录、不写状态标签。

### 6. 去重合并

写入前通读 `AGENTS-LESSONS.md` 与 AGENTS.md：

- 等价条目 → 合并进原有条目，强化表述，不新增编号。
- 相邻主题 → 考虑并成一条，保持每组条目数可控。
- 与 AGENTS.md 硬性约束重复的 → 只留在 AGENTS.md，经验文件不复制约束原文。

### 7. 提议与确认

向用户提交候选清单，按严重程度排序：

```text
P1 高频或高风险 → 建议优先收录
P2 有条件触发 → 正常收录
P3 边缘场景 → 用户决定
丢弃项 → 附一句理由，让用户可推翻
```

用户挑选后，只写入选中的条目，并保持分组结构。

### 8. 写入与验证

- 只改 `AGENTS-LESSONS.md`（或路由决定的目标文件），不动无关内容。
- 写入后通读该分组，确认 Markdown 结构完整、无重复条目。
- 汇报：新增/合并/丢弃各几条，及理由。

## 硬性规则

- 未经用户确认，不写入任何文件。
- 不把无证据的猜测、一次性偶发、情绪化描述写成经验。
- 机械可检查的问题必须优先提议自动化检查，而不是只写说明。
- 不为凑数收录；丢弃要给理由，收录要有证据。
- 不复制 AGENTS.md 已有的硬性约束原文。
- 每次复盘后 `AGENTS-LESSONS.md` 的分组结构保持不变，只增改条目。
