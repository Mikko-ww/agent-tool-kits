# 输出与报告格式

输出结果、生成报告或需要压缩格式时读取本文件。

## 两份产物，缺一不可

`report` 子命令同时产出：

```text
./gh-research/{slug}/
├── brief.md            搜索简报
├── brief.json          简报的机器可读副本
├── candidates.jsonl    唯一事实来源：候选 + 证据 + 分数 + 取证日期
├── evidence/           README 摘录
├── report.md           对话输出的落盘副本
└── report.html         自包含 HTML 报告
```

HTML 内联全部样式，不引用外部字体、脚本或 CDN，离线可打开，跟随系统深浅色。

**HTML 不替代对话输出。** 用户当场要看的是对话里的分级榜单；HTML 承载全量证据与对比表，供事后复查和分享。

## 对话输出模板

```markdown
我将你的需求理解为：[用户目的]。这里的 [产品/名词] 指 [消歧结论与产品指纹]，
因此重点搜索 [类别/形态/工作流]，排除 [不相关类别]。

## A 级：优先研究

### [owner/repo](https://github.com/owner/repo) — 12.4k Stars
- 简介：[一句话说明它是什么]
- 分级：A
- 相似度：92/100 ← [一句话依据]
  证据：`src/nodes/registry.ts:41`（代码搜索，2026-11-24）
- 适合度：88/100 ← [一句话依据]
- 项目质量：84/100
- 近期 Star 趋势：近 30 天 +820（来源，日期）/ 未核验
- 推荐理由：[与用户目标直接对应]
- 注意事项：[许可证、成熟度、部署、开源边界]

## B 级：强模块参考
[同样字段]

## 优先阅读顺序
1. [仓库]：重点看 [产品/模块]
2. [仓库]：重点看 [工作流/模块]
3. [仓库]：重点看 [基础设施/模块]

## 组合建议
[产品层、工作流层、Agent 层、基础设施层如何取长补短]

## 数据说明
- 当前 Star：GitHub，获取于 YYYY-MM-DD
- Star 趋势：[来源与窗口，或「未核验」]
- 分数：根据所引证据近似评估，非客观测量

---
完整报告：`./gh-research/{slug}/report.html`
```

**最后一行必须是 HTML 路径。** 文件确实生成后才给路径；渲染或落盘失败时改为说明未生成及原因，不得给出一个不存在的路径。

## 锚点密度

每个分数后面挂**一条**可核验锚点即可，不要把候选库或全部证据 dump 进对话——那会把榜单淹掉。

- 好：`相似度：92/100 ← 节点画布与自定义节点注册接口均已证实（src/nodes/registry.ts:41）`
- 差：`相似度：92/100`（无依据，只能信）
- 差：把 12 条证据全列在对话里（噪声，应该在 HTML 里）

## 结果较少时

可压缩格式，但以下字段不可省略：链接、当前 Star、简介、分级、推荐理由、HTML 路径。三维分数至少给出有证据的那些，其余标未核验。

## 意图不清时的输出

不要先给一大批仓库，也不要先建目录。先说明为什么选择会分叉，然后问一个问题：

```markdown
「Agent memory」可能指通用记忆 API、知识图谱记忆、编程 Agent 本地记忆，
或完整的有状态 Agent Runtime；这几类的最佳项目不同。

你更想做哪一种？
1. 通用 Memory API（推荐）
2. 编程 Agent 记忆
3. 企业知识/图谱记忆
4. 完整 Agent Runtime
```

用户回答后再检索。若用户明确允许「先给概览」，可以分赛道给少量代表项，但仍要标明类别差异。

## 降级时的输出

| 情况 | 必须说明 |
|---|---|
| `gh` 不可用 | 数值来自网页检索，注明实际来源与获取日期 |
| 代码搜索不可用 | 核心能力只有文档级证据，相似度已按规则封顶 |
| 限流 | 已重试并降级，候选覆盖面受限 |
| 渲染失败 | HTML 未生成及原因，**不给路径** |
| 落盘目录不可写 | 只有对话输出，没有落盘副本，跨会话无法续跑 |

任何情况下都不得用记忆或推测补齐缺失指标。
